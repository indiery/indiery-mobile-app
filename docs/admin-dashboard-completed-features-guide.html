A practical operating manual for the functionality completed from the “Detailed Admin Panel” specification.

Dashboard: http://127.0.0.1:3000/admin/login

Prepared: 16 October 2026
Data policy: live application/database records only; no demo metrics or invented business values.

Purpose and completion statement

Completed: the operational modules documented in this guide are implemented and connected to the Indiery backend. Counts, money, orders, customers, drivers, locations, KYC, payouts, coins, pricing, cancellations, notifications and B2B records are read from or written to application data.

This guide deliberately lists only working capabilities. Features from the original document that are still partial or not integrated are documented separately in Indiery Admin Dashboard — App Integration Gaps.

Before using the dashboard

  1. Start the backend on port 4000 and the website on port 3000.
  2. Open /admin/login.
  3. Sign in with the administrator email and password configured in backend/.env. Credentials are not printed in this guide.
  4. Use the left navigation. The dashboard refreshes backend data automatically and also provides a manual refresh action.
  5. If a module has no application records, it displays an honest empty state rather than sample rows or made-up totals.

1. Dashboard and live operations

The dashboard is the control-room view. It combines data returned by the overview, order, driver, customer, finance, coin and B2B APIs.

What is completed

  • Total and active bookings, searching/unassigned bookings and completed/cancelled outcomes.
  • Registered and online drivers, approved drivers and pending KYC count.
  • Registered customers and customers with loaded active bookings.
  • Recorded gross booking value, platform commission, driver earnings, driver-wallet liability and coins in circulation.
  • Recent driver registrations and attention items based on real KYC and assignment state.
  • GPS map markers only when drivers have submitted coordinates; no fallback driver location is invented.

How to use it

  1. Select Dashboard in the sidebar.
  2. Read the metric cards for the current backend state.
  3. Use the fleet filters to focus on all, online, active-order or offline drivers.
  4. Select a driver marker or fleet card to open that driver’s details.
  5. Review the “Admin attention” list and open the linked driver or order.
  6. Use refresh if immediate synchronization is required; otherwise the view refreshes periodically while visible.
Meaning of zero: a displayed zero means the current query returned zero. “Not available” means the backend does not currently store that value.

2. Orders, dispatch and live tracking

Completed order operations

  • List up to 500 current application orders with search, status and sorting controls.
  • Open complete order details, route, fare split, payment state, customer, driver and delivery timeline.
  • Create a retail/on-demand order using explicitly entered customer, route, vehicle, goods, weight and fare data.
  • Create a B2B order for an existing business client.
  • Assign an eligible online, active, verified and available driver.
  • Advance order status and cancel with a mandatory reason.
  • View actual location freshness and route information where coordinates exist.

Create an on-demand order

  1. Open Orders and choose Create order.
  2. Select Retail or customer order.
  3. Enter customer name/phone, pickup/drop addresses, goods description, weight and total fare.
  4. Select an active vehicle loaded from the backend catalog.
  5. Optionally select an eligible driver; leaving the driver blank creates an unassigned/searching order.
  6. Submit and confirm the new order in the order list.

Assign a driver

  1. Open an unassigned order and select Assign.
  2. Choose from the displayed eligible drivers.
  3. Confirm assignment. The backend rechecks active status, KYC, online state and active-trip availability.

3. Driver management, profile and KYC

Driver list and profile

  • Name, phone, city when supplied, vehicle, plate, online state, KYC state and account state.
  • Current location/speed when supplied, current active order, wallet balance, booking history and payout ledger.
  • Ratings are shown only when stored; new or unrated drivers display “Not rated.”
  • Suspend or reactivate a driver with a recorded reason.

KYC workflow

  1. Open KYC Review and filter the review queue.
  2. Select a driver to view submitted selfie, PAN, Aadhaar, driving licence, RC, insurance and bank documents.
  3. Open an individual document and mark it accepted or rejected. A rejection requires a correction reason.
  4. Approve or reject the complete KYC application.
  5. Return to the Drivers page to confirm the updated eligibility state.
Document truthfulness: missing URLs appear as missing documents. Generated/demo document URLs were removed from the database cleanup.

4. Customer and vehicle management

Customers

  1. Open Customers.
  2. Search by name, phone or email; filter active, suspended, negative-balance or repeat customers.
  3. Open a profile to review registration date, booking totals, completed/cancelled counts, booking value, wallet and coins.
  4. Select Suspend account or Reactivate account, then enter a reason.
  5. Export the current customer list to CSV when needed.

Vehicles

  1. Open Vehicles to review vehicles associated with registered drivers.
  2. Search by driver, category or registration number.
  3. Review category, capacity, RC/insurance submission state, KYC-derived verification and account restriction state.
  4. Use Export registry to download the current filtered data.

5. Payments, payouts, coins and pricing

Customer payments and recorded refunds

  1. Open Payments & Refunds.
  2. Use Customer payments for booking amount, mode, gateway reference and actual payment state.
  3. Use Recorded refunds for cancellations that contain a backend cancellation/refund record.
  4. Export either view to CSV.

Driver payouts

  1. Open Payouts and review eligible driver wallets and KYC/bank readiness.
  2. Complete the real bank/UPI/cash transfer outside the dashboard.
  3. Choose the driver, enter the exact amount, method and external transaction/receipt reference.
  4. Record the payout. The backend deducts the wallet and creates a ledger entry.
  5. Use the payout CSV export for supported banking workflows.

Coins

  1. Open Coin Ledger, select a customer and choose credit or debit.
  2. Enter a positive whole number and a mandatory audit reason.
  3. Apply the adjustment and verify the updated balance and ledger entry.

Vehicle pricing

  1. Open Pricing & Charges and select a backend vehicle.
  2. Edit base fare, per-kilometre rate, partner share, ETA or active state.
  3. Enter a distance to preview the configured fare formula.
  4. Select Save pricing. Values are written to the vehicle record and a change entry is added.

6. Cancellations, support and notifications

Cancellations and disputes

  • Cancelled bookings come from actual order records.
  • The page shows the recorded party, reason, timestamp, penalty and refund.
  • An administrator can add a resolution note; the note is stored in the admin workspace.

Support tickets

  1. Open Support Tickets and choose New ticket.
  2. Enter party, person, related booking when applicable, priority, category and description.
  3. Open the created ticket and move it to waiting or resolved.

Push campaigns

  1. Open Notifications.
  2. Enter the campaign title and message.
  3. Select all customers, all drivers, pending-KYC drivers or customers with active deliveries.
  4. Select Send push now.
  5. Review attempted, accepted and rejected counts returned by the configured Expo push provider.

7. Reports and analytics

Reports are calculated in the dashboard from loaded application orders, customers and drivers. No demonstration revenue curve or synthetic growth value is used.

  1. Open Reports & Analytics.
  2. Select all dates, today, or a rolling 7/30/90-day period.
  3. Filter by a city present in actual customer or driver records.
  4. Review gross booking value, commission, average booking value, repeat-customer rate and booking outcomes.
  5. Review registered/approved/online/pending-KYC drivers and the filtered financial position.
  6. Select Export CSV to download the filtered order report.
Financial figures are computed from stored fare fields. The overview commission uses captured/paid orders; the report view clearly reflects its selected order filter.

8. B2B clients, orders and billing

Create a business client

  1. Open B2B Clients and select the registration action.
  2. Enter business name, contact, phone, email, address, contract type and GSTIN where applicable.
  3. Submit and confirm the new database record.

Create and assign a B2B order

  1. From B2B Clients, choose Dispatch Order, or create a B2B order from the order dialog.
  2. Select the business account; enter pickup/drop, vehicle, goods, weight and fare.
  3. Optionally assign an eligible driver, or leave the order searching for later assignment.
  4. The new order starts with a pending payment state and increases the client’s outstanding balance.
  5. Track it from both Orders and B2B Orders.

Business billing view

  • Business-wise order charges and outstanding balance.
  • Paid/unpaid/draft derived status based on stored payment/outstanding data.
  • Order-wise statement and printable invoice-style view.
  • CSV account-statement export.

9. Administrative records

These modules save real administrator-entered records in the backend workspace. They do not display seeded records.

Service areas

Create and edit city/zone, coverage text, operating hours, category count, manager and administrative active/paused state.

Admin access records

Record a staff member’s name, email, role and service scope. The interface explicitly states that this does not create a login or send an invitation.

Settings and audit

Store company-contact and proposed operational/security configuration. Values remain blank until entered. Controls that are not yet enforced by the runtime are labeled as configuration records. The audit view lists recorded implemented actions such as pricing changes.
